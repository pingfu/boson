# Roadmap

- **Let GitHub Actions build the images.** Collect image builds from GitHub Actions rather than on the Boson server, because today git pull and build on server competes with every running site for processor, memory and disk, and leftover build files pile up until manually cleared. A project would opt in by naming a ready-built image in its compose file; boson then deploys when a build finishes successfully rather than when someone pushes, ties each image to the exact commit it came from so "put commit X back" is a complete instruction, and signs in to GitHub's image store with credentials it already holds for that project. A project with just a Dockerfile keeps working the way it does now.

- **Let a project name the build boson watches for.** Take the workflow filename from the project rather than fixing it at `.github/workflows/deploy.yml`, because today a repository that already has its own workflow layout has to rename a file to suit boson. A project would name the build it wants watched when it is added, falling back to the current filename when it says nothing.

- **Let a repository declare what it deploys, in `_boson.yml`.** Read hostnames, branches and preview rules from a file in the repo on each deploy, because today a repository is added once and gets one branch, one hostname and one port, with a `www` redirect it never asked for. One project would then serve an apex and its aliases, deploy `develop` to a staging hostname beside `main` in production, and give each pull request a container of its own. The work underneath is that the repository is currently the identity of a deployment: the checkout directory, the compose project name, the deploy lock and the unique index all derive from `org/name` alone, and each needs the branch in it before two deployments of one repository can coexist. One webhook still serves them all, since the push event names the ref. Two names claiming the same hostname is a conflict boson refuses and `boson status` reports, alongside anything else the file gets wrong.

- **Give each pull request its own container.** Deploy an open pull request to a hostname of its own and tear it down when the pull request closes, because today a change is only reachable once it is on a deployed branch. The App would subscribe to `pull_request` as well as `push`, which existing installations need reissued permissions for. Previews need a ceiling and an expiry: each one is a full container stack on the same host, GitHub does not redeliver a missed `closed` event, and a preview nobody reaps lives forever. Certificates arrive the way every other hostname's does, as each name first appears, so pointing a wildcard A record at the host is the admin's side of the arrangement.

- **Tag each image with the commit it came from, and keep only the last few.** Build to `<image>:<sha>` rather than overwriting `:latest`, because today every deploy leaves the previous image untagged on disk, nothing removes it, and disk use grows until someone clears it by hand. A tagged history also makes "put commit X back" a redeploy of an existing image rather than a rebuild. How many to keep belongs in `_boson.yml`, next to everything else about the project. The build cache grows too, and needs its own ceiling.

- **Snapshot tests for the Caddy config and the systemd unit.** Compare generated config against a stored copy rather than against expectations written inline, because today both outputs are long enough that an unintended change is easy to miss by eye. A change would show up as a difference to approve or reject.
